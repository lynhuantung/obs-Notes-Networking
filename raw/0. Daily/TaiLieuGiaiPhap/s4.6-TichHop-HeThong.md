## \[4.6\] YÊU CẦU VỀ TÍCH HỢP HỆ THỐNG (INTEGRATION)

### \[4.6.1\] Hệ thống phải cung cấp công cụ, nền tảng lập trình và ngôn ngữ lập trình để xây dựng các chương trình tích hợp hệ thống.

**Mô tả**

- Hệ thống cung cấp cơ chế tích hợp 2 chiều với các hệ thống bên ngoài

- Bao gồm:

  - **Outbound**: từ HRM gọi ra ngoài (ví dụ BHXH, MISA...)

  - **Inbound**: hệ thống ngoài gọi vào để đưa dữ liệu vào HRM

- Đã xây dựng **service tích hợp riêng** để xử lý các luồng dữ liệu này

- Đảm bảo khả năng kết nối linh hoạt và mở rộng với nhiều hệ thống khác

**Giải pháp**

- Xây dựng **service integrate** làm lớp trung gian:

  - Tiếp nhận và xử lý các yêu cầu tích hợp

  - Tách biệt với hệ thống chính để dễ mở rộng

- Outbound:

  - HRM gọi API ra hệ thống ngoài (BHXH, MISA...)

  - Xử lý dữ liệu trước khi gửi

- Inbound:

  - Hệ thống ngoài gọi API vào HRM

  - Tiếp nhận, kiểm tra và lưu dữ liệu

- Hỗ trợ:

  - Kết nối qua API REST/JSON

  - Xử lý real-time hoặc theo nhu cầu

- Ghi log toàn bộ quá trình:

  - Gửi/nhận dữ liệu

  - Thành công/thất bại

### \[4.6.2\] Đối với luồng dữ liệu tích hợp đi từ hệ thống ra bên ngoài (outbound integration) và hệ thống đóng vai trò chủ động (active integration) hoặc bị động (passive integration), hệ thống có cơ chế hỗ trợ tích hợp thông qua Trục tích hợp ESB theo các giao thức chuẩn (ví dụ: REST, SOAP, message queue,\...) và hỗ trợ kết xuất dữ liệu ra bên ngoài và thu nhận dữ liệu từ bên ngoài vào hệ thống theo chuẩn mở (JSON/CSV/Parquet).

**Mô tả**

- Hệ thống hỗ trợ tích hợp dữ liệu 2 chiều:

  - **Outbound**: gọi API từ HRM ra hệ thống bên ngoài

  - **Inbound**: nhận dữ liệu từ hệ thống bên ngoài đưa vào HRM

- Áp dụng mô hình **kết nối trực tiếp (point-to-point)**, không sử dụng ESB

- Sử dụng giao thức **RESTful API (HTTP/HTTPS)** với định dạng **JSON**

- Đảm bảo tích hợp linh hoạt với các hệ thống như BHXH, MISA, TS24...

**Giải pháp**

- Triển khai tích hợp theo mô hình **direct integration** giúp:

  - Giảm độ phức tạp

  - Tăng hiệu năng xử lý

- Sử dụng:

  - REST API chuẩn mở

  - Định dạng dữ liệu JSON

- Hỗ trợ:

  - Gọi API ra ngoài (outbound)

  - Nhận API từ hệ thống ngoài (inbound)

- Bảo mật:

  - Xác thực bằng JWT hoặc API Key

- Kiểm soát:

  - Xử lý lỗi và retry khi thất bại

  - Ghi log toàn bộ quá trình tích hợp

### \[4.6.3\] Toàn bộ thông tin giao tiếp API, data file phải được giám sát trực quan bằng công cụ về các thông tin.

**Mô tả**

- Hệ thống cho phép **giám sát trực quan toàn bộ hoạt động tích hợp API và dữ liệu**

- Theo dõi các thông tin chính:

  - **Trạng thái xử lý** (thành công/thất bại)

  - **Lưu lượng dữ liệu** (số lượng request, tần suất, dung lượng)

- Giúp kiểm soát hiệu năng và phát hiện sớm sự cố

![](C:\Code\HRM-AGENT-AI\HRM-WIKI\obs-Notes-Networking\HRM-Knowledge-Base\src\tlgp/media/image23.png){width="6.873966535433071in" height="3.2222222222222223in"}

**Giải pháp**

- Sử dụng **Prometheus** để thu thập và lưu trữ dữ liệu giám sát

- Thu thập các chỉ số:

  - Số lượng request API

  - Thời gian xử lý

  - Tỷ lệ lỗi

- Kết hợp công cụ hiển thị để:

  - Theo dõi trạng thái theo thời gian thực

  - Quan sát lưu lượng và xu hướng sử dụng

- Thiết lập cảnh báo khi:

  - Lỗi vượt ngưỡng

  - Lưu lượng bất thường

### \[4.6.4\] Các API giao tiếp giữa các hệ thống phải có tài liệu mô tả về version, input, output.

**Mô tả**

- Các API giao tiếp giữa các hệ thống được cung cấp **tài liệu mô tả rõ ràng**

- Bao gồm:

  - Thông tin **input (dữ liệu đầu vào)**

  - Thông tin **output (dữ liệu đầu ra)**

**Giải pháp**

- Xây dựng tài liệu API chi tiết cho từng endpoint:

  - Mô tả chức năng

  - Cấu trúc dữ liệu input/output

  - Ví dụ request/response

- Cung cấp tài liệu tập trung để các hệ thống dễ tích hợp

- Đảm bảo cập nhật tài liệu khi có thay đổi API

### \[4.6.5\] Có cơ chế xác thực phân quyền trong việc giao tiếp qua API và Datafile.

**Mô tả**

- Hệ thống có cơ chế **xác thực và phân quyền riêng cho tích hợp** qua API và Datafile

- Phân tách rõ giữa **tích hợp hệ thống** và **API nghiệp vụ HRM**, tránh sử dụng chung quyền

- Đảm bảo chỉ các hệ thống được cấp quyền mới có thể truy cập dữ liệu

**Giải pháp**

- Sử dụng cơ chế **Secret Key kết hợp Scope** cho từng kết nối tích hợp

- Mỗi hệ thống bên ngoài được cấp:

  - Một **secret key riêng**

  - Các **scope giới hạn phạm vi truy cập**

- Phân quyền theo scope:

  - Chỉ cho phép truy cập đúng chức năng/dữ liệu được cấp

  - Không sử dụng chung token với API nội bộ HRM

- Áp dụng kiểm tra:

  - Xác thực secret key

  - Kiểm tra scope trước khi xử lý request

### \[4.6.6\] Tất cả các ứng dụng phải được tích hợp thống nhất thông qua một Trục tích hợp (ESB) duy nhất thuộc Data Platform. Các ứng dụng không được trao đổi dữ liệu trực tiếp với nhau.

**Mô tả**

- Hệ thống không sử dụng ESB, thay vào đó tích hợp thông qua **API Gateway**

- Các hệ thống không gọi trực tiếp mà đi qua Gateway để quản lý tập trung

- Hỗ trợ tích hợp qua **RESTful API (proxy)**

- Có giao diện UI để cấu hình và quản lý các luồng tích hợp

**Giải pháp**

- Sử dụng **API Gateway** làm điểm trung gian:

  - Kiểm soát truy cập, bảo mật, logging

- Tích hợp qua **REST API (JSON)**

- Cho phép cấu hình nhanh các kết nối tích hợp qua UI

- Hỗ trợ mở rộng cơ chế event-based khi cần
