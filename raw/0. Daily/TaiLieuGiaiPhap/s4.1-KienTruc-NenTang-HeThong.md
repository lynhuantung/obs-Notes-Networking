**Mô tả kiến trúc hệ thống**

- **Client Layer**

  - Người dùng truy cập qua Internet (web/mobile)

  - Tất cả request đi qua **HTTPS (TLS)** đảm bảo mã hóa

<!-- -->

- **DMZ Zone (Edge Layer)**

  - **WAF (Web Application Firewall)**:

    - Lọc các tấn công OWASP (XSS, SQL Injection, CSRF...)

    - Có thể cấu hình rule theo URL/API

  - **Reverse Proxy / Load Balancer**:

    - Terminate SSL (nếu cần)

    - Phân phối request theo thuật toán (Round Robin / Least Connection)

    - Health check để loại bỏ node lỗi

    - Có thể dùng: Nginx / HAProxy / Ocelot

<!-- -->

- **Application Layer (Internal Network)**

  - 2 node **Application Server** chạy song song (stateless)

  - Triển khai theo mô hình **horizontal scaling** (scale theo chiều ngang)

  - Session:

    - Không lưu local → dùng Redis hoặc token (JWT)

  - Khi 1 node down:

    - Load Balancer tự động route sang node còn lại (failover)

<!-- -->

- **Data Layer**

  - **Database (SQL Server)**

    - Mô hình **Active / Passive (Failover)**

    - Có thể triển khai:

      - AlwaysOn Availability Group

      - Log Shipping / Mirroring

    - Passive node sẵn sàng takeover khi Active lỗi

  - **Redis Cache**

    - Dùng cho:

      - Cache dữ liệu (config, lookup, session...)

      - Giảm load DB

    - Triển khai dạng in-memory, latency thấp

  - **File Server (NFS)**

    - Lưu trữ file dùng chung giữa các app node

    - Đảm bảo consistency khi scale nhiều server

<!-- -->

- **DR Site (Disaster Recovery)**

  - Backup dữ liệu định kỳ sang site thứ 2

  - Có thể áp dụng:

    - Backup full + log

    - Replication (future)

  - Phục vụ:

    - Khôi phục khi mất site chính

    - Đáp ứng RPO/RTO

### \[4.1.2\] Dựa trên kiến trúc nhiều lớp

![](C:\Code\HRM-AGENT-AI\HRM-WIKI\obs-Notes-Networking\HRM-Knowledge-Base\src\tlgp/media/image5.png){width="6.260416666666667in" height="4.291666666666667in"}

**Mô tả kiến trúc hệ thống (3-Tier Architecture -- Technical Overview)**

- Hệ thống được thiết kế theo mô hình **3-Tier Architecture**, tách biệt rõ ràng các lớp: Presentation, Application và Database, đảm bảo **tính mở rộng, bảo mật và dễ bảo trì**

**Presentation Layer (Client Layer)**

- Bao gồm các client: **Web và Mobile**

- Giao tiếp với hệ thống thông qua **API (HTTP/HTTPS -- RESTful)**

- Không chứa logic nghiệp vụ, chỉ đảm nhiệm:

  - Hiển thị dữ liệu

  - Gửi request và nhận response

- Hỗ trợ mở rộng linh hoạt nhiều kênh truy cập

**Application Layer (Business Layer)**

- Là lớp xử lý trung tâm, triển khai dưới dạng **Web API / Service (.NET)**

- Bao gồm:

  - **Business Logic**: xử lý nghiệp vụ

  - **Security**:

    - Xác thực (JWT, Auth)

    - Phân quyền theo user/role

  - **Caching (Redis)**:

    - Giảm tải truy vấn database

    - Tăng tốc độ phản hồi

- Đặc điểm:

  - Thiết kế **stateless** để hỗ trợ scale-out

  - Có thể triển khai nhiều instance sau Load Balancer

  - Hỗ trợ retry, logging, monitoring

**Database Layer (Data Layer)**

- Sử dụng **SQL Server** làm hệ quản trị dữ liệu chính

- Chịu trách nhiệm:

  - Lưu trữ dữ liệu

  - Xử lý truy vấn SQL

- Áp dụng:

  - **Backup & Restore** định kỳ

  - **Mã hóa dữ liệu nhạy cảm**

  - Kiến trúc **High Availability (Active/Passive)**

**Luồng xử lý**

- Client → API Request → Application Layer

- Application Layer:

  - Xác thực → xử lý nghiệp vụ → truy vấn cache/DB

- Database → trả dữ liệu → Application → Client

### \[4.1.3\] Hệ thống phải có cơ chế cho phép thiết lập mô hình ứng dụng đa môi trường (Application Landscape) trong triển khai và vận hành hệ thống

**Mô tả kiến trúc đa môi trường (Multi-Environment Deployment Model)**

- Hệ thống được triển khai theo mô hình **multi-environment** gồm: **DEV → TEST → UAT → PRODUCTION**

- Mỗi môi trường được **tách biệt hoàn toàn về hạ tầng, cấu hình và dữ liệu**, đảm bảo:

  - Kiểm soát chất lượng

  - Giảm thiểu rủi ro khi release

  - Đảm bảo tính ổn định khi vận hành

**Quy trình triển khai (Deployment Pipeline)**

- **DEV (Development Environment -- VnResource Server 1)**

  - Developer phát triển tính năng

  - Thực hiện **unit test, integration test**

  - Build source thành **artifact (release package)**

<!-- -->

- **TEST (Testing Environment -- VnResource Server 2)**

  - Deploy từ build DEV

  - Thực hiện:

    - System test

    - Regression test

  - Kiểm tra tính ổn định trước khi bàn giao

<!-- -->

- **UAT (User Acceptance Test -- Server khách hàng)**

  - Deploy bản release đã kiểm thử

  - Khách hàng thực hiện:

    - Kiểm tra nghiệp vụ (business validation)

    - Nghiệm thu hệ thống

  - Có thể kết hợp:

    - Training user

    - Fine-tune cấu hình

<!-- -->

- **PRODUCTION (Production Environment -- Server khách hàng)**

  - Deploy bản đã được UAT approve

  - Sử dụng **dữ liệu thực tế (production data)**

  - Đảm bảo:

    - High availability

    - Monitoring & logging đầy đủ

### \[4.1.4\] Hệ thống phải có cơ chế cho phép sao lưu (backup) và chuyển cấu hình hệ thống (configuration data) hoặc mã nguồn chương trình (source code) thuận tiện, đơn giản và dễ dàng kiểm soát lần lượt giữa các môi trường (Application Landscape) 

![](C:\Code\HRM-AGENT-AI\HRM-WIKI\obs-Notes-Networking\HRM-Knowledge-Base\src\tlgp/media/image29.png){width="6.873966535433071in" height="5.166666666666667in"}

**Mô tả kiến trúc backup & triển khai đa môi trường (Controlled Deployment & Configuration Management)**

- Hệ thống cung cấp cơ chế **sao lưu dữ liệu (backup) và chuyển cấu hình (configuration transfer)** giữa các môi trường **TEST → UAT → PRODUCTION** theo quy trình kiểm soát chặt chẽ

- Việc triển khai được thực hiện thông qua **quản lý phiên bản (versioning) và release package**, đảm bảo:

  - Tính nhất quán giữa các môi trường

  - Khả năng rollback khi cần

  - Dễ dàng kiểm soát và truy vết

**Cơ chế triển khai**

- **Backup & Restore**

  - Hỗ trợ backup dữ liệu định kỳ hoặc theo phiên bản

  - Cho phép phục hồi dữ liệu khi chuyển môi trường hoặc rollback

- **Configuration Management**

  - Cấu hình được tách riêng theo từng môi trường (TEST/UAT/PROD)

  - Không hard-code trong source, đảm bảo linh hoạt khi deploy

- **Release Management**

  - Triển khai bằng **release package (installer/build)**

  - Mỗi bản build có **version rõ ràng**

  - Đảm bảo đồng nhất giữa các môi trường

- **Deployment Flow**

  - TEST → UAT → PRODUCTION

  - Chỉ promote khi đã được kiểm thử và nghiệm thu

**Bàn giao hệ thống**

- Không cung cấp source code

- Bàn giao đầy đủ:

  - **Bản build release (installer/package)**

  - **File cấu hình theo môi trường**

  - **Tài liệu triển khai (deployment guide)**

**Nguyên tắc kỹ thuật**

- Tách biệt:

  - Code (build)

  - Configuration

  - Data

- Đảm bảo:

  - Deploy nhanh, ít lỗi

  - Dễ kiểm soát thay đổi

  - Phù hợp CI/CD hoặc semi-automation

### \[4.1.5\] Hệ thống phải có các khả năng giám sát tự phát hiện lỗi

![](C:\Code\HRM-AGENT-AI\HRM-WIKI\obs-Notes-Networking\HRM-Knowledge-Base\src\tlgp/media/image27.png){width="6.873966535433071in" height="3.3194444444444446in"}

**Mô tả kiến trúc giám sát & logging (Centralized Observability & Alerting)**

- Hệ thống triển khai cơ chế **giám sát, logging và cảnh báo tập trung (centralized logging & monitoring)**, **tách biệt hoàn toàn khỏi ứng dụng**

- Log và metrics không lưu trực tiếp trong application mà được **đẩy ra hệ thống bên ngoài** (ví dụ: Graylog, ELK, Prometheus + Grafana)

- Đảm bảo khả năng **quan sát hệ thống (observability), phát hiện lỗi sớm và xử lý theo đúng vai trò**

**Cơ chế thu thập & xử lý log**

- Ứng dụng:

  - Ghi log theo chuẩn **structured logging (JSON)**

  - Gắn **traceId / correlationId** để liên kết request xuyên suốt

- Logging pipeline:

  - App → Log agent / API → Centralized Logging System

  - Không phụ thuộc DB ứng dụng → giảm tải hệ thống

- Nội dung log:

  - Timestamp, user, API, request/response

  - Exception, stack trace

  - Environment, service name

**Giám sát & phát hiện lỗi**

- **Exception Handling (Middleware level)**:

  - Bắt toàn bộ exception tại tầng global

  - Chuẩn hóa format log lỗi

- **Metrics & Health Check**:

  - Theo dõi CPU, memory, request rate, error rate

  - Health endpoint để kiểm tra trạng thái service

- **Tracing**:

  - Theo dõi luồng request qua nhiều service

  - Phục vụ debug và phân tích nguyên nhân

**Cơ chế cảnh báo (Alerting)**

- Cảnh báo tự động dựa trên:

  - Rule (error rate, timeout, exception...)

  - Threshold (ngưỡng)

- Hình thức:

  - Email

  - Dashboard monitoring

- Phân quyền:

  - Gửi cảnh báo theo vai trò (Dev / Ops / Admin)

**Tuỳ biến & quản lý**

- Cấu hình:

  - Mức log: Info / Warning / Error / Trace

  - Rule cảnh báo theo module hoặc service

- Quản lý log:

  - Lưu trữ tập trung

  - Tìm kiếm nhanh theo traceId

**Mô tả kiến trúc Cloud (IaaS)**

### \[4.1.8\] Hệ thống cung cấp cần đảm bảo quy trình xử lý tập trung. Việc truy xuất và cập nhật các giao dịch là tức thời vào cơ sở dữ liệu tập trung. Tất cả các chi nhánh từ xa được kết nối trực tuyến với hệ thống ứng dụng tập trung để đảm bảo khả năng sử dụng các thông tin nhất quán tại mọi địa điểm và mọi thời điểm.

Hệ thống được thiết kế theo mô hình **xử lý tập trung**, đảm bảo dữ liệu được cập nhật tức thời và nhất quán trên toàn hệ thống.

Giải pháp

- **Kết nối trực tuyến**

  - Các chi nhánh truy cập hệ thống qua Internet/VPN

  - Sử dụng chung một hệ thống trung tâm

- **Xử lý & cập nhật tức thời**

  - Giao dịch ghi nhận trực tiếp vào **database tập trung**

  - Dữ liệu hiển thị real-time

- **Dữ liệu nhất quán**

  - Không phân mảnh dữ liệu

  - Đồng bộ tại mọi thời điểm, mọi địa điểm

  - Đảm bảo dữ liệu nhất quán, cập nhật gần real-time

- **Kiến trúc mở**

  - Thiết kế modular hoặc microservice

  - Dễ tích hợp hệ thống bên ngoài

- **Mở rộng linh hoạt**

  - Triển khai độc lập từng module

  - Không ảnh hưởng toàn hệ thống

### \[4.1.10\] Hệ thống cần có khả năng tham số hóa dễ dàng và linh hoạt tại thời điểm cài bặt ban đầu và duy trì, phát triển trong tương lai.

### \[4.1.14\] Hệ thống phải đảm bảo cơ chế mã hóa thông tin dữ liệu truyền thông giữa máy trạm và máy chủ trong suốt phiên làm việc. Đảm bảo thông tin truyền thông không bị đánh cắp bởi bên thứ ba.

  - Xác thực kết nối (authentication)

### \[4.1.15\] Hệ thống phải có khả năng mã hóa các dữ liệu nhạy cảm như thông tin mật khẩu tài khoản người dùng, thông tin số tài khoản ngân hàng

**Mã hóa dữ liệu trong cơ sở dữ liệu:** Toàn bộ dữ liệu nhạy cảm được mã hóa bằng thuật toán AES-256 và bảo vệ thông qua hệ thống quản lý khóa tập trung (KMS) hoặc HSM (Hardware Security Module) để đảm bảo rằng chỉ có những người có quyền hạn mới có thể truy cập

![](C:\Code\HRM-AGENT-AI\HRM-WIKI\obs-Notes-Networking\HRM-Knowledge-Base\src\tlgp/media/image10.png){width="6.873966535433071in" height="6.722222222222222in"}

**Mô tả**

- Hệ thống áp dụng cơ chế **mã hóa và băm (hashing) dữ liệu nhạy cảm** nhằm đảm bảo an toàn thông tin người dùng và dữ liệu quan trọng

- Dữ liệu nhạy cảm như mật khẩu, thông tin cá nhân và tài chính được bảo vệ ở mức lưu trữ (data at rest)

**Giải pháp**

- **Mật khẩu người dùng**

  - Không lưu dạng rõ (plain text)

  - Áp dụng cơ chế **hash một chiều**:

    - Sử dụng thuật toán mạnh (SHA-256 hoặc tương đương)

    - Kết hợp **salt ngẫu nhiên** cho từng user

  - Có thể mở rộng:

    - Iteration (multiple rounds) để tăng độ bảo mật

- **Dữ liệu nhạy cảm khác** (SĐT, tài khoản ngân hàng, CCCD...)

  - Mã hóa **2 chiều (symmetric encryption)** khi lưu DB

  - Chỉ giải mã khi có quyền truy cập hợp lệ

  - Khóa mã hóa được quản lý an toàn (không hard-code)

- **Lưu trữ an toàn**

  - Dữ liệu được mã hóa tại database

  - Kiểm soát truy cập chặt chẽ theo quyền

  - Ghi log truy cập dữ liệu nhạy cảm

- **Quản lý khóa mã hóa:** Các khóa mã hóa được lưu trữ và quản lý một cách an toàn, giúp đảm bảo dữ liệu luôn được bảo vệ và chỉ có thể giải mã khi có quyền truy cập hợp lệ.

- **Cô lập CSDL:** Cơ sở dữ liệu được cô lập và không kết nối trực tiếp với Internet, bảo vệ hệ thống khỏi các cuộc tấn công trực tuyến.

- **Quản lý quyền truy cập:** Các tài khoản kết nối với cơ sở dữ liệu sẽ có quyền hạn hạn chế, đảm bảo không có truy cập trái phép vào dữ liệu quan trọng.
