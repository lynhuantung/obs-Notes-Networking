### 8.2.1 Hệ thống phải hỗ trợ mô hình kiến trúc đa tầng (multi-tier), bao gồm ít nhất 3 tầng sau: Tầng Giao diện: Giao diện người dùng; Tầng Ứng dụng: Yêu cầu đáp ứng đầy đủ các chức năng, quy trình xử lý nghiệp vụ. Hệ thống có thiết kế mở để dễ dàng tích hợp hoặc mở rộng trong tương lai. Tầng Cơ sở dữ liệu: Yêu cầu có sự phân vùng dữ liệu hợp lý để đảm bảo hiệu năng truy suất dữ liệu đạt tốc độ xử lý tối đa. Vui lòng mô tả chi tiết từng tầng của giải pháp được đề xuất.

##### Kiến trúc Đa Tầng (Multi-Tier Architecture) --- VnResource HRM

> ![[image131.png]]
>
> Hệ thống VnResource HRM được thiết kế theo mô hình kiến trúc 3 tầng (3-Tier Architecture), tách biệt rõ ràng giữa tầng giao diện, tầng ứng dụng và tầng cơ sở dữ liệu nhằm đảm bảo khả năng mở rộng, hiệu năng, bảo mật và dễ dàng tích hợp trong tương lai.

##### Tầng 1 --- Presentation Layer (Tầng Giao diện)

> Tầng giao diện cung cấp khả năng truy cập hệ thống thông qua trình duyệt Web và Mobile App trên các nền tảng Windows, Linux, macOS, iOS và Android. Hệ thống sử dụng giao diện responsive, tự động tương thích với nhiều kích thước màn hình và không yêu cầu cài đặt phần mềm tại máy người dùng.
>
> Tầng này chỉ thực hiện chức năng hiển thị dữ liệu, gửi request và nhận response từ Application Layer thông qua giao thức HTTPS/TLS 1.2/1.3 và RESTful API (JSON), không chứa business logic nhằm đảm bảo tính bảo mật và dễ bảo trì.

##### Tầng 2 --- Application Layer (Tầng Ứng dụng)

> Tầng ứng dụng được xây dựng trên nền tảng .NET Web API theo kiến trúc stateless, xử lý toàn bộ business logic của hệ thống như tuyển dụng, nhân sự, chấm công, tiền lương, đào tạo và đánh giá.
>
> Hệ thống hỗ trợ:
>
> JWT, OAuth2 và RBAC cho bảo mật và phân quyền
>
> Redis Cache để tối ưu hiệu năng
>
> API Gateway và Integration Service phục vụ tích hợp hệ thống ngoài
>
> Retry, Audit Log, CorrelationId cho xử lý tích hợp
>
> Kiến trúc được thiết kế mở, hỗ trợ REST API và mô hình microservice-ready, cho phép triển khai và mở rộng độc lập từng module mà không ảnh hưởng toàn hệ thống.
>
> Để đảm bảo High Availability, hệ thống triển khai nhiều App Server chạy song song phía sau Load Balancer (Nginx/HAProxy), hỗ trợ failover tự động khi xảy ra sự cố.

##### Tầng 3 --- Data Layer (Tầng Cơ sở dữ liệu)

> Tầng dữ liệu sử dụng Microsoft SQL Server 2019 Standard triển khai theo mô hình Active/Passive High Availability bằng AlwaysOn Availability Group hoặc Log Shipping.
>
> Hệ thống áp dụng nhiều cơ chế tối ưu hiệu năng:
>
> Index tối ưu theo nghiệp vụ
>
> Query optimization cho dữ liệu lớn
>
> Paging và lazy-load
>
> Redis Cache giảm tải truy vấn SQL
>
> File Server NFS tách lưu trữ file khỏi Database
>
> Dữ liệu được lưu trữ theo chuẩn UTF-8/Unicode, hỗ trợ đầy đủ tiếng Việt và đa ngôn ngữ.
>
> Các dữ liệu nhạy cảm như lương, CCCD và tài khoản ngân hàng được mã hóa AES-256. Toàn bộ truy cập Database đều thông qua Application Layer, đồng thời hệ thống ghi nhận Audit Log và kiểm soát truy cập theo nguyên tắc quyền tối thiểu nhằm đảm bảo an toàn dữ liệu và tuân thủ bảo mật hệ thống.
